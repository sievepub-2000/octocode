# validate-idea

Systematically evaluate whether an idea is worth pursuing.

## When to use

- The user has a product, feature, or business idea and wants a reality check.
- A go/no-go decision is needed before committing resources.
- Multiple ideas need comparative evaluation.

## Instructions

1. **Restate the idea** in one clear sentence including: what it does, who it's for, and what problem it solves.
2. **Problem validation**: Is the problem real? How do people currently solve it? What's the pain level (1–10)?
3. **Solution fit**: Does this solution address the core pain? Are there simpler alternatives?
4. **Market sizing**: Estimate TAM/SAM/SOM with rough numbers and assumptions.
5. **Competitive landscape**: List 3–5 existing solutions. What's the unfair advantage?
6. **Feasibility check**: Technical complexity (low/medium/high), time to MVP, key dependencies.
7. **Risk assessment**: Top 3 risks and their mitigations.
8. **Verdict**: Score on a 1–10 scale across desirability, feasibility, and viability. Give a clear GO / PIVOT / NO-GO recommendation with reasoning.
9. If comparing multiple ideas, present a comparison table.
