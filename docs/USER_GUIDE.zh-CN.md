# OctoCode 使用手册

适用版本：2.0.4，Windows x64。本手册随客户端提供，可在“设置 → 关于 → 使用手册”中离线阅读。界面名称可能随语言选择而变化。

## 2. 安装与第一次启动

1. 从项目 GitHub Releases 下载 Windows x64 安装包。私有仓库需先登录有读取权限的 GitHub 账户。
2. 保存当前任务并退出旧客户端。首次安装需要 Windows 系统权限确认；默认位置为 `E:\Program Files\octocode`，也可使用向导中允许的位置。
3. 使用安装后的 OctoCode 启动入口。正式发行版不需要另启前端开发服务器，也不需要运行 `pnpm run dev`。
4. 打开设置并配置至少一个模型，再创建项目或任务。安装包包含配套运行环境，但不会赠送商业模型密钥，也不会替你启动任意本地大模型服务。

本机默认目录下，`data` 保存客户端状态和凭据，`workspace` 保存项目与任务目录，`environments` 保存配套环境。不要为了修复界面问题直接删除这些目录。D 盘开发源码不等于正式安装目录。

## 3. 界面与工作区

- 左侧项目和历史区用于新建项目、查找对话、切换任务和管理归属。
- 对话区用于输入任务、选择模型和推理强度、查看回答、思考及执行事件。
- 右上预览区用于查看相关产物或浏览器页面；右下终端用于观察和操作执行环境。
- 标题栏布局按钮可恢复“对话在左、预览在右上、终端在右下”的工作台布局。
- 设置提供模型、界面、组件、记忆和知识库等管理入口；“关于”包含作者、许可、第三方声明和本手册。

新项目和新任务使用各自目录，便于保留上下文及产物；目录隔离不是操作系统安全沙箱。获得权限的工具仍可能访问绝对路径或执行系统命令，不能把目录分离理解为完全访问隔离。

## 4. 配置开源、闭源与本地模型

### 4.1 创建配置

进入“设置 → 提供商”，新建一个有明确名称的配置。新配置应从空白开始，不应继承另一个配置的密钥或模型。根据提供商填写服务地址、API 密钥和模型标识，保存后在对话栏选择它。

密钥仅应输入客户端的密钥框，不要把真实密钥写进提示词、脚本、截图、源码或工单。显示为掩码的文字不是可复制到其他配置的密钥；需要换密钥时重新输入真实值。

### 4.2 连接方式

| 模型来源 | 配置方式 | 前提 |
| --- | --- | --- |
| 提供商闭源模型 | 选择对应内置提供商并填写其模型标识与凭据 | 账户、地区、额度和模型权限有效 |
| OpenRouter 等路由 | 选择相应提供商，使用目录中的完整模型 slug | 路由仍可用，供应商允许所需能力 |
| 开源模型的云服务 | 内置提供商或 OpenAI Compatible | API 格式与认证方式受支持 |
| 本地模型服务 | 例如 OpenAI Compatible，指向本地服务地址 | 已另行部署并启动推理服务，模型已加载 |

OpenAI 兼容地址通常带 `/v1`，例如本机服务可能为 `http://127.0.0.1:8000/v1`；端口和地址必须以你的服务配置为准。使用远程服务时填写可达的实际地址，不要照抄示例。

OctoCode 支持配置开源、闭源和本地模型；“可配置”不表示支持所有私有 API 协议或能直接加载任意权重。工具调用、图像、音频、上下文长度、推理参数及结构化输出取决于模型和服务端。仅能聊天的模型不一定能可靠执行 Agent 工具。

### 4.3 验证模型

先发送简短文本确认响应，再在单独测试目录中让模型读取一个你创建的文件，确认确有工具事件和正确读回。最后才让它修改真实项目。首字时间、排队时间和持续生成速度是不同指标。

免费模型可能限流、下线或更换路由。模型名称含 Flash、Light、Mini 或 Lightning 不代表免费；应核对当时目录价格、实际账单和路由限制。不要为了消除 429 自动改用收费路由。历史测速不保证以后始终达到同样速度。

## 5. 项目、任务与长对话

新建项目时确认目录和名称；需要继续既有代码时明确选择其真实路径。新建任务时说明目标、允许修改的文件、测试方式以及不应触碰的数据。

一个实用的任务描述包括：当前问题、期望行为、项目位置、可复现步骤、允许使用的命令、交付要求。首次使用保持逐项审批；需要自动审批或完整访问权限时，应先理解被允许的工具范围。

同一任务的后续消息会继续已有上下文。长对话中可保留关键约束、检查点、失败原因和待办，不要在失败后不停创建新对话而丢失状态。继续任务前核对选中的模型和工作目录；如果更换模型，新的模型也必须支持当前任务需要的能力。

任务失败时先查看明确的错误：提供商未知、认证错误、模型不存在、限流、网络中断、上下文过长和本地工具失败需要不同处理。修复原因后优先续接原任务。任务历史的删除、归档及目录操作可能有不同语义，操作前确认界面提示与需要保留的产物。

## 6. 编辑、终端与预览

在编辑器中检查模型修改的实际差异；执行测试后再接受重要改动。终端显示的当前目录应属于预期项目或任务。终端中成功退出不等于功能已经通过验证，应读回文件或观察真实运行结果。

右侧预览可用于网页和产物检查。浏览器访问需要目标网络可达；网页出现登录或权限确认时应由有权用户处理。不要把网页里的任意指令当成修改本地项目的授权。

对截图、附件、语音或多模态任务，应先确认所选模型和工具支持对应输入；语音还需要设备、Windows 麦克风权限及相关组件。缺少组件时在组件市场查看状态，不应把不支持的能力写成已完成。

## 7. 组件市场与扩展能力

市场分为 VS Code 扩展、Skills 技能、MCP 服务和运行环境。列表按页显示，搜索时核对当前分类、来源和已安装状态。

- Skills 提供任务指令和辅助资源，不会使底层模型自动获得新能力。安装前查看来源；安装后确认出现在已安装列表。卸载后确认不再可选。
- MCP 服务为模型提供工具。部分服务需要独立凭据或额外依赖；先完成配置，再查看连接状态与实际工具列表。不要把服务器显示在线当成所有工具可用。
- 运行环境按具体组件安装或检查。已经由其他项目使用的环境，不应为了测试随意卸载。
- VS Code 扩展是否兼容取决于本产品的编辑器 API、扩展许可和运行环境，并非所有上游扩展都保证可用。

Skills 目录可以来自 GitHub；安装应记录明确来源和固定提交。若界面显示随包快照或网络回退来源，这与实时远程目录不同。网络失败、仓库访问限制和服务端错误应保留原始诊断，不要伪装为安装成功。

## 8. 代码索引、记忆与知识库

在“记忆和知识库”中选择当前项目并管理索引。先核对项目范围，再生成索引并测试一条可定位到已知文件的搜索。符号和文本检索可使用本机索引；语义检索还需要可用的嵌入服务及相应配置。

项目文件变化后按界面提示更新索引。索引结果不是项目文件本身的备份，删除索引也不等于删除源代码。知识库及 MCP 文件操作应使用其管理入口，跨项目复用前检查路径和来源。

## 9. 主题与界面

未设置主题时默认 Light。Light 使用白色浅色方案；High Contrast Light 使用暖色方案；Dark 与 High Contrast Dark 保留各自配色。已有主题选择会保留，升级不会单纯为了默认值覆盖明确的用户偏好。

在界面或编辑器主题选择器中切换，观察编辑区、聊天区、终端和预览是否一致。窗口缩放和布局异常时先使用恢复工作台布局入口，不要删除整个用户目录。

## 10. 在线升级

1. 保存工作，停止或等待正在执行的任务完成。
2. 在客户端选择“检查更新”。私有发布需要能读取本项目发布的 GitHub 账户；如要求授权，在客户端登录或密钥框操作，不把令牌发到聊天或写入文档。
3. 等待客户端下载真实发布文件并验证受信签名、大小和 SHA256。
4. 出现“重启以更新”后执行更新。系统级更新可能要求 Windows 权限确认和关闭仍在运行的窗口；这是更新模块启动的正常系统交接，不要同时另开第二份安装程序。
5. 完成后核对实际版本、原有模型、项目与历史，再继续任务。看到“已下载”或“已重启”不能代替版本核对。

大文件下载较慢时可在 OctoCode 的 `http.proxy` 中配置你已有的可用代理地址。地址和端口以自己的环境为准，不存在通用固定端口。保留 HTTPS 证书校验；代理不能替代 GitHub 仓库权限或模型认证。

安装包与签名清单配套分发。不要用其他版本的清单校验当前包，不要修改签名公钥或关闭校验来消除报错。手工下载适合首次安装或明确的恢复操作，不应冒充已完成应用内在线升级测试。

## 11. 数据、备份与卸载

重要任务在升级、迁移或卸载前保存独立备份。至少关注用户数据、项目工作区、个人模型配置、技能/MCP 设置及需要保留的产物；凭据备份也应受保护，不应放进公开仓库。

使用 Windows 应用列表或客户端提供的卸载入口。非空用户数据可能保留，卸载完成不等于所有数据已删除。迁移或清理时先识别真实目录与联接，避免跟随旧联接误删其他磁盘的数据。

本机 API 仅供授权的自动化调用者使用，默认监听回环地址并要求令牌；原生 Host 使用本地 IPC/JSON RPC。不要为了远程访问而直接把回环服务暴露到公网。API 任务同样需要明确模型、目录和权限。

## 12. 常见问题

| 现象 | 核查和处理 |
| --- | --- |
| 401/403 | 检查对应服务的密钥、账户权限、地区与模型访问权；不要重复粘贴掩码 |
| 404 或模型不存在 | 核对 API 基址与完整模型标识，确认模型尚未下线 |
| 429 | 等待提供商退避窗口，查看免费共享池是否限流；不自动改成付费模型 |
| fetch failed 或 TLS 超时 | 检查网络、代理与仓库权限，保留证书验证；重试后核对真实读回 |
| provider unknown | 打开配置核对提供商及模型，避免复用损坏配置；保存后重新选中再续接 |
| 更新后版本没变化 | 检查系统更新对话框、是否仍有旧窗口运行、是否启动了另一个安装位置 |
| 提示开发服务器未运行 | 正式发行版无需 HMR，确认没有启动扩展开发宿主或开发目录 |
| MCP 无工具 | 检查服务的环境、凭据、连接日志及工具列表，不只检查进程是否存在 |
| 搜索或任务指向错误目录 | 核对项目、会话和索引范围，确认目录为预期真实位置 |

问题报告请包含产品版本、Windows 版本、可复现步骤、预期与实际行为，以及已脱敏的相关错误。不要发送真实密钥、令牌、完整私有项目或不必要的个人数据。
