# OctoCode 0.1.8 / Desktop 1.132.2

This release repairs terminal restoration and diagnostic placement on the Windows desktop, and hardens the production daemon after migration to machine 2.

- Moving a terminal between editor groups no longer unregisters its live resource. Terminal restoration registers its resolver before editor restoration begins.
- Terminals and Output channels use the lower-right editor group. Missing panes are restored before opening diagnostic output; a separate bottom panel is no longer used as a fallback.
- Runtime execution errors are shown in the execution terminal. Normal provider cancellation preserves the original abort error and does not emit an error log; genuine failures still do.
- Daemon startup is serialized. A stale token with no listener is handled as a cold start; an existing daemon must pass identity, store-root and authenticated-attachment checks. Normal application restarts preserve daemon sessions and credentials.
- Routine and goal HTTP responses omit persisted model API keys. Bearer authentication supports non-ASCII input, and resumed goals clear obsolete completion/error metadata.
- The log settings view is included in source control instead of being excluded by the generic `logs` rule. CI Node and pnpm defaults match the declared project toolchain.
- The small demo GIF is stored directly in Git so fresh checkouts do not depend on the missing Git LFS object. Rust build output is excluded from source publication.
- Windows build inputs now include the MCP smoke helper and agent CLI launcher in version control, rather than requiring ignored files left by an earlier build.
- Final VSIX packaging always stages native binaries instead of restoring an archive cached only by JavaScript output. Extracted package hashes are checked against the rebuilt binaries.
- Native supervisor checkpoint initialization is atomic; detached worktrees honor the requested base revision; opening a newer database schema is rejected without rewriting its version marker.
- Windows daemon processes are detached from Electron's child job and unreferenced during desktop relaunch. Real Electron tests verify that the daemon can survive its parent's normal exit; normal application exit still stops its owned daemon.
- Malformed advisor template settings return a terminal error instead of panicking. Omitted supervision configuration uses the same intervention and retry defaults as an empty configuration object.
- Real remote branches containing `HEAD` remain visible; symbolic remote HEAD references are excluded. Relative worktree removal resolves against the requested repository and removes the registered identity.
- Failed project creation rolls back database assignments and removes its newly owned index directory. Successful initial indexes include their assigned sessions.

The authoritative machine-2 paths remain `D:\Program Files\OctoCode` for the application and `D:\gpt-workspace\octocode\runtime` for data, workspace and environments. Existing user data and machine-3 files are preserved.

Validation and deployment evidence are recorded separately in the machine-2 acceptance report. Source tests alone do not establish production, clean-install or restart acceptance.
