# OctoCode 2.1.0

桌面 2.1.0，核心扩展 0.1.21。提供 Windows x64 系统安装包和签名发布清单。

## 长程任务与对话接续

- 模型直接返回上下文超限时，Harness 和 Host 将明确的超限状态传给后台和桌面。后台在新对话接续未完成任务，避免重复加载已超限的检查点。
- 接续时保留任务目标、最新用户要求、计划、排队消息和已有产物。旧对话可查阅，新对话继续使用同一项目和既有权限。任务明确要求只读时，接续也遵守该要求。
- 后台 HTTP 运行在换对话后保持同一运行 ID，可查看接续后的会话链。目标任务和继续会话的定时任务跟随最新对话。
- 同一条接续链最多自动切换三次。达到上限后仍可手动接续。预填充内存保护保持独立生效。

## 依赖与桌面修复

- `fast-xml-parser` 升级到 5.12.0，覆盖桌面和构建工具的两项 Dependabot 告警。[GHSA-474x-hrwr-fgx4](https://github.com/advisories/GHSA-474x-hrwr-fgx4)
- Windows 原生 CLI 的 `pageant` 升级到 0.2.5。[GHSA-662x-8wvj-2276](https://github.com/advisories/GHSA-662x-8wvj-2276)
- 修复 Windows 随附 Node 下自定义 TypeScript 工具的编译。首次配置模型前可保存通知、字体等普通设置，补齐各界面的模型选择提示。

## Windows 验证

从已安装的 2.0.8 原位升级到 2.0.9 候选包后，核对了工作区文件、设置、技能、钩子和会话数据库。候选版正常冷启动并打开聊天面板。用实际安装的后台、Host 和 Harness 对接隔离的测试模型，验证超限后创建新对话、原 API 运行完成及旧产物保留。该场景覆盖 Windows 接续链路，模型返回由测试服务控制。

扩展与界面测试、Rust Host、Windows 原生 CLI、后台 Python 和桌面构建测试均通过。本版安装包和扩展由 `octocode-release.json` 记录大小、版本和 SHA-256，附带 Ed25519 签名。
