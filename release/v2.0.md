# OctoCode 2.0 候选版

本候选记录由 [2.0.1 修复版本](v2.0.1.md) 接续；下文保留此前构建的版本与验收边界。

桌面内部版本：2.0.0；核心扩展：0.1.13。分发平台：Windows x64。

## 修复内容

- Skills 市场改为接入 Agentic Awesome Skills 的 GitHub 稳定清单，支持本地检索和分页；随包目录快照注明来源与日期，慢网时先显示快照并继续读取在线清单。技能按固定提交的独立子目录下载，保留路径、链接、大小和覆盖校验及上游许可证，不再依赖 skills.sh 的发现接口。
- 逐项修复实际 Python、Windows MCP、OpenSec、llmwiki 运行时依赖告警，并将依赖锁和官方归档纳入可复现构建；安装时重新绑定 Python 命令到正式 E 盘解释器。
- 正式安装与安装验收目录统一为 `E:\Program Files\octocode`；用户数据、工作区和运行环境迁移为 E 盘真实目录，D 盘仅用于开发。
- 设置入口紧邻账户上方，隐藏更新入口不再留下空行；设置分组标题加大加粗，二级菜单使用较小字号。
- High Contrast Light 改为白色和中性浅灰；Dark 使用黑底、炭灰、白灰文字及棕铜色强调；High Contrast Dark 单独保留原 Dark 的紫灰底色和品牌红强调色。客户端外壳、对话、启动底色及主题预览同步，切换主题不会互相覆盖。
- 修复设置修改恢复原值后仍提示未保存、索引设置保存与丢弃不同步的问题；保存失败时保留编辑。
- 接入固定上游版本的 Google Harness² 任务递归，通过 OctoCode 本地 API 使用已有模型；项目内保存采纳的提示，不跨项目复用。Windows 接入范围及实际验收以 `docs/HARNESS2.md` 为准。

- 修复已确认的依赖漏洞。存在未提供上游补丁的依赖时，移除依赖或保留真实上游版本并提供有攻击回归的源码补丁；原有 GitHub 告警仍须在主分支更新后逐项复扫确认。
- PowerShell 执行窗口使用 VS Code 原生终端，每个对话拥有自己的 shell 进程与工作目录，支持输入、回车和真实命令执行。
- 未选择对话时，原生终端使用当前工作区目录，不再默认进入用户主目录。
- 本地 API 保留模型错误事件中的信息，避免任务结束后失败原因变成空值；失败会话可明确续接。
- 安装初始化只在 MCP 配置内容需要迁移时写入文件，保留未变化配置的原始格式、编码和文件哈希。
- 更新 zstd 0.14.3、zstd-safe 8.2.0、zstd-sys 2.1.2、tonic 0.14.7 和 async-compression 0.4.51，修复压缩上下文复用泄露及相关内存安全问题；替换已撤回的 crypto-bigint 0.7.8。
- 修复原生终端的 ConPTY DLL 与 OpenConsole 未解包，导致点击后终端立即退出、界面为空的问题；构建门禁检查这些实际依赖。
- 修复 Windows 普通盘符路径与 `\\?\` 规范路径前缀不一致，导致已有项目产物索引被误判越界；保留真正的目录越界和链接保护。
- 修复干净卸载留下的旧 Python 元数据遮蔽新版 MCP 信息的问题；仅将确认失效的元数据移至保留备份，后续初始化失败时回滚。安装初始化失败会返回非零错误码。
- 多个编辑器窗口通过本地认证管道共享一个 Host，避免重复打开同一个数据库导致 host exited (1)。RPC 回复、任务事件和关闭取消分别绑定所属窗口。
- 修复关闭窗口后托盘单击和右键 Open 无法恢复主界面；独立扩展测试不再连接生产守护程序。
- 修复 Python 守护程序解释器退出时读取 stdin 的崩溃，以及正常会话退出被误报为 actor 崩溃的问题。
- 修复 QuickDiff 模型释放后异步回调访问空模型的异常。
- 保留项目、对话、原生终端、附件和产物的所有权检查；新项目与新对话使用各自目录。
- 左侧统一使用组件市场入口，移除 MCP、Skills 的独立快捷入口；Agent 角色归入 Skills。
- 插件、Skills、MCP 和运行环境统一每页最多 20 项，底部提供数字页码和前后页；已安装组件置顶，市场结果按来源排名排序。接入真实市场搜索、分页和安装。
- 索引管理与项目代码搜索并入设置的“记忆和知识库”。复用现有原生代码索引，支持离线符号和文本检索、重启加载与清除；按当前项目路由，不需要额外建立数据库。
- 对话中的推理、执行和回答使用居中时间标记，精确到秒，格式为 `--2026-10-18 12:59:07--`；保留事件时间，重新加载历史不会改成当前时间。
- 长对话仅挂载可见消息，保留原 Markdown、代码、工具和附件交互；修复加载历史、跨越虚拟列表阈值及流式回答时的阅读位置跳动。
- 修复续接任务启动失败后对话一直停留在“启动中”、无法再次发送的问题；保留原任务和历史，不自动无限重试。
- 修复终端子进程同时继承 `NO_COLOR` 和 `FORCE_COLOR` 所导致的 Node 警告；本地、流式和原生 PTY 路径统一处理。
- 为 PDF 软蒙版函数增加递归与节点上限、数值范围检查，为工作流元数据解释器补齐字符串、数组和映射容量限制。
- 随产品提供的独立 Node 运行时升级为官方安全版本 26.12.1（内置 Undici 8.12.2、OpenSSL 3.5.9），npm 升级为经官方 SHA-512 核验的 12.2.1；与 Electron 自身运行时分别核验。
- Electron 升级为 43.8.3，并对内嵌 Node 24.22.0 分别核实原生 TLS/Brotli 补丁、DNS/TLS 输入防护和 HTTP 连接投毒回归。共享启动入口使用维护中的 Undici 8.12.3；旧式 Node HTTP/HTTPS Agent 暂停复用已使用连接，因此该路径可能增加网络握手延迟，模型流式请求的 Undici 连接池继续复用。自定义 Node 启动快照及 Node permission 模式不在当前产品支持范围内，不能将配置下不触发解释为原生漏洞已修补。
- Rust 依赖按最新 RustSec 数据库复核，升级 russh 至真实上游 0.64.1 并保留已有本地修复，更新受影响的密码库、证书根及 Tokio 补丁版本；三套正式锁文件均无漏洞与撤回版本警告。最终打包二进制仍须使用这些锁重新构建并验收。
- 私有 GitHub 更新支持加密保存的 classic PAT 和 GitHub 登录；主更新与独立全量安装恢复通道校验固定 Ed25519 公钥签名及安装包 SHA-256，CDN 跳转不携带 GitHub 凭据。最终双通道安装仍列入下方发布门槛。
- 修复两个登录入口异步等待后继续使用失效服务访问器，导致登录成功却没有继续检查更新的问题；未登录时的后台检查等待登录，手动检查仍提供认证操作。
- 修复并发更新检查互相使 GitHub 授权结果过期、反复读取会话的问题；仅真实认证会话变化才更新版本标记。
- 修复 OpenAI 兼容模型信息自动刷新被记为用户修改、离开设置时误报未保存的问题；用户主动更换模型和编辑参数仍正常提示保存。
- 构建锁定依赖、检验 VSIX 内的新 Host/harness/code-graph/broker、拒绝带运行数据的打包目录，更新第三方完整许可证。

## 发布门槛

源码与攻击回归通过后，还需最终 Windows 安装包在本机卸载旧程序后重新安装、冷启动、原生操作回归、GLM5.3 API 回测，以及 GitHub 默认分支 Dependabot 重新扫描。当前仍是候选版，没有发布 2.0 安装包。

Windows 正式安装与测试目录为 `E:\Program Files\octocode`，D 盘仅用于开发。卸载程序保留运行数据、项目和凭据；新安装前逐项记录用户数据哈希，并先将旧版指向 D 盘的运行数据联接迁移为 E 盘实际目录。

发布和安装验收通过、确认远端可取回全部源码与发布记录且正式安装不依赖源码目录后，删除本地源码副本和开发临时产物。保留正式安装、用户项目、运行数据和登录凭据。

目录隔离避免状态误复用，不等同于操作系统安全沙箱；旧会话保留原目录。Linux/macOS/Docker 和在线更新未执行完整安装验收，不属于本次 Windows 安装包的验证结论。
