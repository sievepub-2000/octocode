OctoCode 全面评估：架构、模块与竞品对照

覆盖本轮三批任务（4 号机模型修复、11 项优化、第三批 8 项）。数据来自固定用例评测、单元测试与本机实测；竞品信息来自公开资料（2026-08 至 09）。

结论：OctoCode 现在是一个能在本地模型上稳定完成日常编程与网页任务的桌面 Agent。本轮修掉了三个“看起来像模型问题、实为工程问题”的根因：权重分片损坏、Clash 把局域网模型走了代理、记忆目录被按会话隔离。同时补齐了思考档位、免 key 搜索和 HTTP 接入。它与 Claude Code、Codex 的差距不在工具数量，而在模型能力上限和长任务自主性（回退链、旁路审查、云端常驻）。

架构

三棵源码树加一套运行环境。桌面壳只负责界面，Agent 逻辑全部在 Rust 进程里，通过两层协议串起来：扩展 ↔ host 是 stdio JSON-RPC，host ↔ harness 是每次运行一个进程加 JSONL 事件流。

分模块评估

评级：成熟 可直接依赖；可用 满足日常但有已知短板；薄弱 需要投入。

模型接入（provider）

成熟

41 个 provider，每个都能获取模型列表并保存；OpenAI 官方与兼容入口已分开；base URL 优选列表可按“有线优先、Wi-Fi 回落”配置。短板：不会自动发现本地服务（Ollama、LM Studio 等），omp 能做到。

思考 / 推理档位

成熟

优先按元数据、其次按名称族识别，区分两类实现：effort 型（GPT-5、o 系列、Claude 4 等）和模板开关型（Qwen3、GLM、DeepSeek 等），一路贯通 UI、host 和 harness。实测 oMLX 上只有 enable_thinking 能关闭思考，reasoning_effort 无效，映射已按此设计。服务端返回 400/422 时自动去掉思考参数重发。

执行循环（harness）

成熟

源自 xAI grok CLI 的 Rust 实现：流式工具调用、hashline 编辑、子 Agent、后台命令、monitor 和 todo 闸门。本轮加了 extra_body 透传和思考降级，重试上限改为 4 次（原先 502 连续重试 15 次，每次约 100 秒）。短板：没有模型回退链。

系统提示词

成熟

唯一来源是 MiniJinja 模板，设置页预览在构建时自动同步。新增环境、长任务、记忆、网页和写后诊断各段，删掉重复内容和写错的工具名。身份由环境变量强制为 OctoCode，修复了经 OpenRouter 调用时模型自称 Grok 的问题。

记忆

成熟

现在只有一套：harness 记忆（Markdown + BM25，纯本地），所有会话共享，并由 dream 定期整理。记忆用例从失败变为通过，用时 139 秒降到 43 秒。桌面会话与 HTTP API 会话共用同一份记忆。知识类内容沉淀到 llmwiki，两者分工已写入提示词。

长程、压缩与续跑

可用

32k 上下文的长任务经过多次自动压缩仍能完成，resume 用例通过。短板：压缩用例耗时从 1500 秒涨到 2700 秒，因为触发的压缩轮次更多；也没有 Prime Agent 或 Codex 那样的云端常驻和心跳。

代码智能与调试

成熟

code_intelligence 的 14 个 LSP 动作、debug_session 的 27 个 DAP 动作，都与 oh-my-pi 一一对应，而且直接复用 VS Code 已加载的语言服务和调试适配器。提示词已要求改完代码先查诊断。

网页与浏览器

可用

harness 的 web_fetch 已开启，可访问任意域名。Scrapling 设为默认工具：免 key 搜索按 Bing → Brave → DuckDuckGo → Mojeek 顺序回退；get 带浏览器指纹抓取；fetch 用本地 Chrome 渲染。另有工作台浏览器和 obscura。短板：本机出口会被部分搜索引擎弹验证码；工作台里的 search_web 和 fetch_url 在生产环境从未注册，属于死代码。

技能

成熟

默认 28 个技能：superpowers 全套、ponytail 家族、Agent-Reach 等，来源记录在 SKILLS_SOURCES.txt，自检脚本会校验这份清单。

界面

成熟

对话栏贴边并加上下边线，模型名右侧有档位选择器；角标方向已改正；历史列表去掉复选框，运行中显示旋转沙漏，结束后显示粗线圆圈。webview 的相关测试全部通过。

外部接入

可用

新增 FastAPI HTTP API：支持创建运行、查询、SSE 事件流、取消和续跑，/docs 自带交互文档。默认只监听本机，对外监听必须配置令牌。已实测完成任务并续问。短板：需要手动启动，没有托盘开关；还没有 TS/Python SDK 封装。

定位

  • 相对 Claude Code 和 Codex：工具面已经接近，LSP 和调试甚至更完整。真正的差距是模型能力和云端长任务能力。OctoCode 的优势在于数据不出局域网，而且能用自有硬件上的开源模型。
  • 相对 OpenCode 和 oh-my-pi：同属多 provider、偏开放的路线。OctoCode 多了完整的 IDE 界面和 VS Code 语言服务。omp 的回退链、advisor 和 TTSR 可以借鉴，已列入下一步。
  • 相对 ZCode：产品形态最接近（桌面 ADE），但 ZCode 绑定 GLM 且必须联网，OctoCode 不绑定模型。
  • 相对 Prime Agent：它的“持续精炼 harness”思路，与 OctoCode 的“记忆 → dream 整理 → 技能”闭环方向一致。它的 daemon 常驻能力值得参考。
